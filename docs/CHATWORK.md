# Chatworkの制約と、この実装の扱い

確認日：2026-09-11。仕様は変更される可能性があります。導入前には末尾の公式資料と実サンプルで再確認してください。

## 最大100件は履歴ページングではない

メッセージ一覧APIは1ルーム最大100件です。`force=0`の差分取得は、任意の過去時点から繰り返し遡れるページングではありません。この版は`force=1`で最新範囲を重ねて取得し、DBのIDで重複を除きます。100件取得して既知IDとの接点がない場合は、欠損の可能性を記録します。再び数件取得できたというだけでは、その疑いを消しません。

既知IDの個別取得は、一覧取得とは別のAPIです。今回のアダプターにもありますが、全履歴のIDを無制限に発見できるという意味ではありません。API上限は5分300回を前提に設計を確認し、実ユーザー数・部屋数・権限確認回数を合わせて計算します。分散レート制御はこの版の完成範囲ではありません。

## エクスポートの基準時点

管理者エクスポートは日次のログ取得時点を基準とし、ダウンロード時刻と同じではありません。管理者の実行回数・対象チャット・組織内ユーザーの現在参加状況等の条件があります。ダイレクトチャットが含まれること、マイチャットは対象外であること、編集・削除前の本文を含める設定があることにも注意します。

通常の社内検索と管理監査用のログは目的が異なります。この版では承認グループの通常本文だけを検索対象にし、DM・マイチャット・未承認ルームを取り込み時から除外します。管理用の生ログをGCS等へ一時保存する場合は、検索サービスの読取権限から分離し、保持期限を設けます。

## 実CSVの列とIDは未確定

このリポジトリは**正規化CSVの契約**を実装しています。Chatworkから現在出るCSVを無加工で投入できると保証していません。実サンプルで、ルームID、メッセージID、発言者ID、発言時刻、編集・削除表現、文字コードを確認してください。

| 正規化列 | 必須 | 意味 |
|---|---|---|
| `room_id` | 必須 | ルームの数字ID |
| `account_id` | 必須 | 発言者の数字ID |
| `sent_at` | 必須 | Unix秒、またはタイムゾーン付きISO 8601 |
| `body` | 必須 | 本文。HTMLや本文の命令は実行しない |
| `author` | 任意 | 表示名。なければ発言者ID |
| `message_id` | 任意 | 本当に取得できた安定したメッセージID。内部IDを代入しない |
| `updated_at` | 任意 | 編集・削除のバージョン時刻。なければ発言時刻 |
| `deleted` | 任意 | `true/false`または`1/0`。削除を明示する |

マニフェストには `snapshot_at`、`coverage_from`、`coverage_through`、`room_ids`、`complete_snapshot: true` を含めます。すべての時刻にタイムゾーンを付けます。列名を対応づける場合は `columns: {"room_id": "ルームID", ...}` を指定できます。`encoding`は既定UTF-8 BOM対応です。

本文が「削除されました」等に一致するだけでは勝手に削除と判断しません。実データの仕様で確認した場合だけ`deleted_marker`を指定します。本文・編集履歴を一列に合成した形式の場合は、単なる列名対応ではなく事前変換が必要です。

同一日時・同一本文の発言が複数あるとIDなし履歴を安全に一対一で識別できない場合があります。その場合は重複を残し、誤った削除・統合を避けます。ID付き発言が最新一覧から外れたことも削除の証拠にはしません。

## Webhookの役割

作成・編集通知は速報性を高める補助経路です。公式仕様の再送なし・10秒以内のHTTP 200応答を前提に、署名を検証しDB受信箱へ保存してから200を返します。重い反映処理は`drain-webhooks`で分離します。

この版は削除通知を仮定しません。設定数上限や自動無効化、通知欠損があるためWebhookだけで完全同期とは扱いません。設定を列挙・再有効化する管理機能は未実装です。PoCの反映ワーカーは1つに限定します。失敗はエラーコードで記録し、自動的に何度も本文を再処理する方式にはしていません。

## 既存認証との関係

Chatworkアクセストークンの短い有効期間と、refresh token／`offline_access`の条件を確認します。ここではOAuth認可・更新を作り直さず、既存PoCが更新する認証情報を利用します。アカウントIDの対応と現在参加を毎回確認し、認証失効時は検索を停止します。

## 初回移行で合意すること

最新ログ収集を先に開始し、後から得る履歴スナップショットと期間を重ねます。「CSVを受け取った時間以降だけ取る」という分割は避けます。取得対象外の部屋・空白期間・削除反映の遅延を記録します。現在参加しているユーザーに参加前の発言まで見せてよいかは、会社の方針として明文化します。参加期間別のACLはこの版では実装していません。

添付ファイルについて、ログ内のリンクとファイル本体は別です。この版は添付PDF等の本文抽出・検索をしません。元サービスから削除されたリンクの有効性も保証しません。
